## 問題

以下は同じ結果になる。どちらが望ましいか。

```python
df_titanic.group_by("Pclass").agg(
    CountOver30=pl.col("Age").filter(pl.col("Age") >= 30).len()
).sort("Pclass")
```

```python
df_titanic.filter(pl.col("Age") >= 30).group_by("Pclass").agg(
    CountOver30=pl.len()
).sort("Pclass")
```

## 当初の結論

通常は後者。

理由:

- 条件に合う行だけを集計する意図が直接読める
- SQL の `WHERE → GROUP BY` に対応している
- 単純な集計では分かりやすい

## 実行計画

前者:

```text
SORT BY [col("Pclass")]
  AGGREGATE[maintain_order: false]
    [col("Age").filter([(col("Age")) >= (30.0)]).len().alias("CountOver30")] BY [col("Pclass")]
    FROM
    DF ["PassengerId", "Survived", "Pclass", "Name", ...]; PROJECT["Age", "Pclass"] 2/12 COLUMNS
```

後者:

```text
SORT BY [col("Pclass")]
  AGGREGATE[maintain_order: false]
    [len().alias("CountOver30")] BY [col("Pclass")]
    FROM
    simple π 1/1 ["Pclass"]
      FILTER [(col("Age")) >= (30.0)]
      FROM
        DF ["PassengerId", "Survived", "Pclass", "Name", ...]; PROJECT["Pclass", "Age"] 2/12 COLUMNS
```

## 実行計画から見た考察

前者の方がノード数が少なく、実行計画はシンプルに見える。

ただし

- 実行計画が単純
- コードが読みやすい
- 性能が良い

は別問題。

Polars の optimizer により、見た目だけで性能優劣は判断できない。

## より重要な視点

後者:

```python
df.filter(pl.col("Age") >= 30).group_by("Pclass").agg(pl.len())
```

意味:

> 30歳以上だけ残し、その件数を数える

前者:

```python
df.group_by("Pclass").agg(
    pl.col("Age").filter(pl.col("Age") >= 30).len()
)
```

意味:

> 各グループ内で条件付き集計を行う

## 前者の知識は有用か

有用。

むしろ Polars を使い込むほど重要。

例:

```python
df.group_by("Pclass").agg(
    Total=pl.len(),
    Over30=pl.col("Age").filter(pl.col("Age") >= 30).len(),
    Over50=pl.col("Age").filter(pl.col("Age") >= 50).len(),
    MeanOver30=pl.col("Age").filter(pl.col("Age") >= 30).mean(),
)
```

このように

- 総数
- 条件別件数
- 条件別平均

を1回の `group_by().agg()` にまとめられる。

これは

> 集約式の中でデータ加工する

という Polars 的な発想。

## 結論

両者は用途が異なる。

### 後者が向く

```python
df.filter(...).group_by(...).agg(...)
```

- グループ化前に全体へ条件を適用
- 単純集計
- 意図が直接的

### 前者が向く

```python
df.group_by(...).agg(
    pl.col(...).filter(...)
)
```

- 条件付き集計
- 複数条件を同時集計
- Polars の表現力を活かせる
- 応用範囲が広い

### 最終評価

- この具体例だけなら後者が読みやすい
- Polars の知識としては前者の理解の方が価値が高い
- 実務では両方使い分けるのが理想
